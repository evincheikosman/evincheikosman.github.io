IRC Escalation Hub

Integrity, Risk & Compliance Escalation Hub

A unified platform replacing 4 disconnected tools—handling the complete lifecycle of high-stakes compliance decisions, from submission to searchable archive, across a 1,000+ person organization.

Timeline ~12 weeks
Production Diffs 100+
Rollout 1,000+ person org in under 3 weeks
Status Launched & live

⚠ The Problem

IRC's escalation process handled the organization's highest-stakes regulatory compliance decisions — the ones too complex or consequential for any single team to own, requiring cross-functional input from engineering, ops, policy, legal, and product to reach consensus. I owned the entire lifecycle: intake, facilitation, stakeholder coordination, decision documentation, and tracking outcomes through to resolution.

Every step of that process was manual and fragmented. Requests came in through forms, status lived in spreadsheets, context was scattered across threads, and past decisions were buried in documents nobody could find. There was no searchable archive, no audit trail, no visibility into what was in-flight — and no institutional memory to build on. Every escalation started from zero.

⚙ What I Built

A unified escalation management platform handling the complete lifecycle from submission to decision archival. I designed the system architecture, taught myself to code, and shipped it entirely without engineering support.

  • Searchable decision archive — 90+ historical decisions indexed and queryable
  • AI-powered assistant for querying past decisions and process guidance
  • Structured submission and admin review queue with approval workflow
  • 7-section analytics dashboard with deep-links to underlying data
  • Automated presentation deck generation with completion detection
  • Auto-created Google Chat spaces on approval — 11 stakeholders added automatically
  • Scheduled reminders for upcoming meetings via calendar integration
  • Dynamic announcements and alerts widget
  • Collaborative discussion threads tied to each decision record
  • Integrated feature request and bug reporting portal — all submissions triaged, prioritized, and resolved independently; 95–98% of requests shipped within days of submission

◎ Technical Integrations

  • Google Slides API — programmatic deck generation with slide completion detection; decks auto-populate on escalation approval
  • Google Chat API — automated space provisioning and member management triggered by approval workflow events
  • Google Calendar API — event creation and scheduling wired directly into the submission and approval flow
  • Chronos (scheduled job orchestration) — time-based reminder triggers for upcoming escalation meetings
  • LLM / AI integration — natural language Q&A layer over 90+ indexed decisions; surfaces relevant precedent without manual search
  • Internal regulatory data API — deep-linked data pulls into the analytics dashboard
  • Claude Code — used throughout development for code generation, debugging, and iterative feature work

✦ What I Learned

This was the first production tool I'd ever shipped — built on the job, learning to code while managing the program simultaneously. The user base set the bar: VPs, Directors, and senior cross-functional leaders making high-stakes regulatory decisions. That pressure was clarifying. Every confusing UI element costs credibility with that audience. I learned what "production-quality" actually means from people who wouldn't accept anything less.

The real challenge wasn't technical — it was adoption. Replacing something people had relied on for years meant bridging the gap between the old mental model and the new one. I ran office hours, did 1:1 walkthroughs, fixed anything confusing the same day it was flagged. What I didn't expect was how fast it clicked: within the first month, people weren't just using it — they were bringing others along. VPs were turning around decisions faster. Escalation velocity went up. The tool sold itself once people touched it; my job was making sure they actually touched it.

The outcome I hadn't planned for: other Meta programs started reaching out, wanting to build something similar for their own escalation protocols. Because the codebase was already solid, they could build on top of it rather than starting from scratch. The tool scaled into programs I never designed it for — not because I promoted it, but because it was good enough that other people wanted it.
